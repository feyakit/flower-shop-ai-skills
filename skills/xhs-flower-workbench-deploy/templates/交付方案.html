03实测结论（在自有服务器上已跑）

步骤结果
装 uv 0.13.9 + uv sync通过，12 个依赖 0.6 秒
check-login 首次运行自动拉起本地桥，监听 127.0.0.1:9333，提示「浏览器扩展未连接」
Chromium 加载 extension/扩展连上，is_extension_connected = True
导航 creators 后台通过，title = 小红书创作服务平台
fill-publish 填表失败：Bridge 错误: 页面加载超时

结论：桥接链路（①→④）全部打通，卡点在网络，不在代码。

坑一：海外 / 机房 IP 会被小红书屏蔽（最隐蔽）

症状

www.xiaohongshu.com 返回 404、浏览器被跳到 www.rednote.com；creator.xiaohongshu.com 返回 200 但 <div id="app"> 是空的，截图纯白，于是报「页面加载超时」。

不是装坏了。发布链路只能在客户国内网络下验证；扩展和桥接在海外照样通。

对策：客户梯子必须让小红书直连，不能全局代理。预检第一项就是「她能手动打开小红书后台并看见内容吗」。

坑二：跳到 rednote.com 就失能

扩展 manifest 只授权了 xiaohongshu.com，跳国际站后报 Cannot access contents of url "https://www.rednote.com/". Extension manifest must request permission to access this host.
修法：把 https://*.rednote.com/* 加进 host_permissions 与 content_scripts.matches。

坑三：扩展加载没法脚本化

chrome://extensions 是浏览器内部页面，脚本点不了。两条路：--load-extension 启动参数（用独立 user-data-dir，不然污染客户日常浏览器；Chrome 已在跑会忽略参数，先退出），或打包 crx + 企业策略（重，只有做产品才值）。

坑四：9333 单实例

重复开任务会 OSError: [Errno 98] address already in use。清理时用 pkill -f "bridge_serve[r].py" 这类带字符类的写法——普通写法会匹配到自己的 shell 命令行并把它杀掉。

07远程交付方式（UU 远程）

选它的理由：基础远控免费、不限时长次数、无广告、被协助方不用注册账号；画质（当前 4K 免费）足以看清后台和二维码——向日葵免费版压到 720P 以下，二维码容易扫不出。

发给客户的话

1. 打开 https://uuyc.163.com/download/ 下载 Windows 版装上
2. 打开后进「设置 → 安全」，把「允许他人远程协助」打开
3. 回到「远程协助 → 开始协助」，把「本设备 ID」和「验证码」发我
4. 不用注册账号，装完就能用

另外两件事：
- 装好后先关掉，右键图标 →「以管理员身份运行」再开一次
- 电脑别锁屏、别睡眠，插上电源

三个坑

  • UAC 弹窗会黑屏。装软件需要管理员权限，一旦弹 UAC，Windows 切到安全桌面，远程画面黑掉。让客户以管理员身份启动 UU 远程，它才带管理员令牌接管弹窗。这条不做，装到一半必卡。
  • 协助方要登录，被协助方不用。别让客户去注册。
  • 用完刷新验证码；若后续还要维护，可保留「允许他人远程协助」开关，下次直接报 ID。
Tailscale 只适合做维护通道

它只是网络层：跑命令要 sshd（Windows 默认没有），看屏幕要 RDP（Win 专业版才有）。首次交付用 UU 远程开门，进去后顺手装 Tailscale + sshd，之后维护走命令行——别指望首次就纯隧道完成。
